# Desafio DS v33 — Plano de implementação

## Objetivo

Criar uma versão piloto com 21 aulas de conteúdo real, organizadas por turno, turma e disciplina, preservando os 121 IDs históricos, o progresso local, o EduAuth e o fluxo simplificado da v32.

## Fase 1 — Base e compatibilidade

- utilizar a v32 como base;
- preservar IDs, perfil, sessão, Classroom e EduAuth;
- manter o código coletivo de uma hora somente para iniciar a aula;
- manter 10 minutos como mínimo técnico e 15–25 minutos como duração pedagógica prevista;
- não exigir integração externa nas 21 aulas piloto.

## Fase 2 — Novo modelo editorial

Cada piloto recebe:

- tema e situação real;
- o que é e para que serve;
- história ou contexto tecnológico quando aplicável;
- aplicação profissional e empresas reais verificadas;
- exemplo explicado;
- prática guiada;
- laboratório ou simulador interno;
- guia de VS Code quando aplicável;
- retomada;
- quatro questões de fixação;
- atividade final e critérios;
- códigos para copiar e baixar.

## Fase 3 — Laboratório interno

Criar componentes reutilizáveis para:

- sequência de algoritmo;
- editor e saída controlada;
- comparação entre linguagens;
- classificação de requisitos;
- HTML/CSS com pré-visualização;
- JavaScript em sandbox;
- decisões de inovação;
- organização empresarial;
- testes de módulos Python;
- compilação C simulada;
- game loop e delta time;
- DOM e cadastro;
- API simulada;
- comparação mobile;
- viewport responsivo;
- PWA e offline.

## Fase 4 — Aulas piloto por turma e disciplina

### Manhã — 1º DS

#### Introdução à Programação
1. Algoritmos, entrada, processamento e saída.
2. Primeiro programa em Python.
3. Python comparado com JavaScript, C e Java.

#### Análise e Método para Sistemas
4. Levantamento de requisitos.
5. Requisitos funcionais.
6. Requisitos não funcionais.

### Manhã — 2º DS

#### Programação Front-End
7. HTML semântico aplicado.
8. CSS responsivo aplicado.
9. Variáveis e tipos em JavaScript.

#### Inovação Tecnológica e Empreendedorismo
10. Tecnologias de mercado e problemas reais.
11. Análise de uma startup real.
12. Estrutura de uma empresa tecnológica.

### Manhã — 3º DS

#### Programação no Desenvolvimento de Sistemas
13. Python estruturado, módulos e testes.
14. Linguagem C e compilação.
15. Game loop e física 2D.

### Noite — 2º DS Subsequente

#### Programação Front-End
16. JavaScript aplicado a orçamento.
17. DOM aplicado a cadastro de clientes.
18. API aplicada à consulta de dados.

#### Programação Mobile
19. Tipos de aplicações mobile.
20. Mobile-first aplicado a serviço profissional.
21. PWA e funcionamento offline.

## Fase 5 — Experiência por público

### Manhã

- blocos visuais;
- exemplos de escola, aplicativos, jogos e tecnologia;
- curiosidades;
- animações explicativas leves;
- exploração opcional.

### Noite

- linguagem direta e profissional;
- exemplos de orçamento, clientes, serviços e trabalho de campo;
- menos animações;
- tipografia e áreas de toque maiores;
- uma entrega útil por aula.

## Fase 6 — QA

- verificar os 21 IDs;
- verificar duração prevista de 15–25 minutos;
- confirmar ausência de dependência externa;
- validar quatro questões por aula;
- validar códigos copiáveis e baixáveis;
- validar prática e atividade final;
- validar celular, tablet e Chromebook;
- validar JavaScript e JSON;
- confirmar ausência de chave privada no pacote público.

## Fase 7 — Entrega

- ZIP público v33.0 piloto;
- pacote completo v33.0 piloto;
- painel EduAuth sincronizado;
- relatório de implementação;
- validação final;
- checksums SHA-256.

## Limite desta versão

A v33.0 é uma versão piloto. As 21 aulas usam o novo padrão. As outras 93 permanecem disponíveis no padrão anterior para não interromper o uso, até a aprovação do piloto.
