# P7.3 — Preview Seguro Isolado — v14.2

Data: 15/08/2026.

## Objetivo

Separar a execução de HTML/CSS/JavaScript digitado pelo aluno do documento principal de Atividades, permitindo uma CSP mais estrita sem retirar o preview didático.

## Arquitetura

`atividades/index.html` carrega `preview/index.html` em um iframe `sandbox="allow-scripts"`. O Preview Host mantém a infraestrutura de controle em módulo externo e cria um segundo iframe sandboxado para o documento do aluno. O documento do aluno é entregue ao iframe interno por URL Blob.

A página principal não injeta mais o HTML do estudante em `srcdoc`. Ela envia o conteúdo ao Preview Host por `postMessage`. O canal é inicializado antes da primeira execução com token aleatório gerado por `crypto.getRandomValues`; mensagens de retorno só são aceitas da janela do Preview Host e com o token do canal.

## CSP

A aplicação principal de Atividades remove `unsafe-inline` de `script-src` e `style-src`. `unsafe-eval` já havia sido removido na P7.2. `wasm-unsafe-eval` permanece por causa do runtime Python/Pyodide.

O Preview Host possui política própria e limitada. `unsafe-inline` existe somente nessa superfície isolada, porque exercícios legítimos precisam executar `<style>` e `<script>` escritos pelo aluno. O iframe interno não recebe `allow-same-origin`, formulários privilegiados, popups ou navegação do topo.

## UI sem estilo inline

Os indicadores que usavam `style="width:..."` foram migrados para elementos `<progress>`. Assim a CSP principal não precisa de `style-src 'unsafe-inline'`.

## Autoridade

Nenhuma autoridade pedagógica, econômica ou de segurança mudou. Salvamento continua em `student-files`, conclusão em `activity-progress`, inspeção de código continua antes da execução e o preview não concede XP, moeda ou liberação.

## Backend

Não requer SQL, migration, RLS ou Edge Function nova.
