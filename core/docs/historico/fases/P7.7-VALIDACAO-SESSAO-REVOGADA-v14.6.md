# P7.7 — Validação de Sessão Revogada — v14.6

## Objetivo
Fechar a janela residual em que um access JWT ainda não expirado poderia continuar operando após a revogação administrativa da sessão.

## Implementação
- Nova migration `031_p77_live_session_guard.sql`.
- RPC `security_is_auth_session_active_service(user_id, session_id)` acessível somente por `service_role`.
- O JWT é primeiro validado por `auth.getUser()`. Em seguida, o claim `session_id` é comparado server-side com `auth.sessions`.
- Sessão ausente/revogada retorna `401 session_revoked`.
- Guard indisponível retorna `503 session_guard_unavailable` (fail closed).
- 18 Edge Functions críticas receberam o guard.
- A sessão compartilhada do frontend apaga o token local imediatamente quando recebe `session_revoked`.

## Ordem de deploy live
1. Se a P7.6 ainda não foi aplicada, executar `030_p76_auth_session_revocation.sql`.
2. Executar `031_p77_live_session_guard.sql`.
3. Republicar as Edge Functions listadas em `release-v14.6.json` com `verify_jwt=true`.
4. Testar com dois dispositivos: revogar no Admin e confirmar `401 session_revoked` no dispositivo revogado antes do `exp`.
5. Rodar Security/Performance Advisors.
6. Só depois ativar `authSessionRevocationReady=true` no Admin.
