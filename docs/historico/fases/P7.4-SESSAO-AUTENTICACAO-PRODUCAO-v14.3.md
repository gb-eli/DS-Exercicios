# P7.4 — Sessão e Autenticação em Produção — v14.3

Data: 15/08/2026.

## Objetivo

Tornar a sessão institucional mais resiliente em celular, múltiplas abas e redes instáveis, sem transformar falhas temporárias de conectividade em logout permanente.

## Refresh coordenado

A camada `core/session/agv-session.js` continua usando a chave Supabase canônica `sb-<project-ref>-auth-token`. O refresh agora é serializado entre abas usando `navigator.locks` quando disponível. Navegadores sem Web Locks usam um lock temporário em `localStorage`, com expiração curta e reaproveitamento de uma sessão mais nova gravada por outra aba.

Antes de renovar, a camada relê a sessão canônica. Se outra aba já renovou o token, a sessão nova é reutilizada em vez de renovar novamente com um refresh token antigo.

## Rede instável

Falha de rede, timeout ou estado offline não apaga mais o refresh token local. A sessão só é removida automaticamente quando o endpoint de Auth rejeita definitivamente o refresh com erro 400/401.

Ao voltar para a aba, recuperar foco ou voltar ao estado online, a camada verifica silenciosamente se o token está perto de expirar e tenta renová-lo.

## Logout

O logout da camada comum solicita explicitamente `scope=global` ao endpoint Auth e sempre limpa a sessão local da aba. A propagação entre abas continua pelo `storage` event.

## Senha temporária

O Hub raiz não trata mais `must_change_password=true` como sessão pronta para navegação normal. O usuário é enviado para Atividades, onde já existe o fluxo obrigatório de criação de senha pessoal.

## Admin — encerramento de sessão

O botão existente foi renomeado para **Encerrar sessões de atividade**. A interface agora declara explicitamente que essa ação fecha `activity_sessions`, mas não garante revogação imediata de tokens Auth já emitidos.

A revogação administrativa de Auth por usuário foi mantida como pendência de backend. O conector Supabase ao vivo ficou indisponível nesta fase, portanto não foi criada nem publicada uma ação de revogação sem verificação do schema/API real.

## Backend

Não requer SQL, migration, RLS ou Edge Function nesta versão.
