# P7.5 — Segurança de Autenticação Server-Side — v14.4

Data: 2026-08-15

## Objetivo
Impedir que contas privilegiadas com senha temporária (`profiles.must_change_password = true`) usem endpoints administrativos/pedagógicos sensíveis, mesmo que o navegador tente acessar a função diretamente.

## Hardening aplicado no pacote
Os seguintes snapshots de Edge Functions agora consultam `must_change_password` e retornam `403 password_change_required` antes de operações privilegiadas:

- `staff-dashboard`
- `admin-profile-user`
- `admin-roster`
- `staff-directory`
- `agv-teacher-activity`
- `security-telemetry` (ações administrativas)

`lobby-moderation` e `supervision` já possuíam bloqueio equivalente e foram mantidos.

Admin e Professor tratam `password_change_required` e encaminham o usuário para `../atividades/`, onde está o fluxo obrigatório de definição da senha pessoal.

## Revogação de sessões Auth
Não foi simulada nem declarada como concluída. O conector Supabase ao vivo ficou indisponível durante a P7.5 antes da inspeção/deploy das Edge Functions.

A documentação atual do Supabase confirma que logout/revogação elimina refresh tokens/sessões afetadas, mas um access token JWT já emitido pode continuar válido até o `exp`. Para garantias mais fortes em operações altamente sensíveis, deve-se validar o `session_id` contra a sessão Auth ativa ou usar uma estratégia equivalente server-side.

## Implantação necessária
Para que o hardening server-side desta versão passe a valer no projeto Supabase ao vivo, é necessário republicar as seis Edge Functions alteradas listadas acima com `verify_jwt=true`.

Não há SQL/migration nesta versão.
