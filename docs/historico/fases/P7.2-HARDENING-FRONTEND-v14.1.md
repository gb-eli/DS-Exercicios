# P7.2 — Hardening do Frontend — v14.1

Data: 2026-08-15

## Objetivo
Reduzir a superfície de execução e injeção no frontend sem quebrar o ambiente prático de HTML/CSS/JavaScript/Python dos alunos.

## Alterações aplicadas

1. **CSP de Atividades endurecida com compatibilidade pedagógica**
   - removido `unsafe-eval` de `script-src`;
   - mantidos `unsafe-inline` e `wasm-unsafe-eval` somente porque o preview executa código didático digitado pelo aluno e o runtime Python usa Pyodide/WebAssembly;
   - `worker-src` foi reduzido para `'self'` (o Worker é local);
   - acrescentados `frame-src 'self'`, `media-src 'none'` e `manifest-src 'self'`.
2. **Preview isolado**
   - iframe continua com `sandbox="allow-scripts"`;
   - continua sem `allow-same-origin`, `allow-forms`, `allow-popups`, downloads ou navegação do topo;
   - adicionado `referrerpolicy="no-referrer"`.
3. **HTML dinâmico sensível reduzido**
   - mensagens de apoio, acomodações e feedback docente agora são construídas com `textContent`/DOM, não `insertAdjacentHTML`;
   - resumo de política da supervisão também usa DOM/textContent.
4. **Autoridade preservada**
   - nenhuma alteração em RLS, sessão, liberação, conclusão, recompensa, carteira ou Edge Function.

## Decisão consciente
Não é seguro remover `unsafe-inline` nesta fase sem separar o preview do aluno em um documento/host de execução próprio. Fazer isso diretamente quebraria CSS/JS inline legítimo digitado pelos alunos. Uma fase futura pode criar um Preview Host dedicado e então deixar a CSP da aplicação principal totalmente sem `unsafe-inline`.

## Validação
- `node --check` nos módulos alterados;
- teste P7.2 para CSP/sandbox/DOM seguro;
- suíte completa do ecossistema.
