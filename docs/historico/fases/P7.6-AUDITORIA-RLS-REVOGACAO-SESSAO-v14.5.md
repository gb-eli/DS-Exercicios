# P7.6 — Auditoria RLS e Revogação de Sessão — v14.5

Data: 15/08/2026

## Objetivo
Preparar a revogação administrativa real de sessões Auth e reforçar a auditoria de permissões sem declarar mudanças live que não puderam ser verificadas.

## Implementado no pacote
- `030_p76_auth_session_revocation.sql`: RPCs `service_role` only para contar/remover sessões em `auth.sessions`.
- `admin-auth-sessions`: Edge Function JWT-only para Admin/Super Admin, com gate `must_change_password`, auditoria e encerramento simultâneo de `activity_sessions`.
- Auditoria local `core/tools/audit-supabase-security.mjs` para `SECURITY DEFINER`, search_path, grants/revokes, service_role no frontend e gates privilegiados.
- Admin recebe configuração para a nova função, mas a ação fica desabilitada até o backend live ser implantado e validado.

## Importante
O conector Supabase ficou indisponível durante a P7.6. Portanto:
- migration 030 NÃO foi aplicada;
- `admin-auth-sessions` NÃO foi publicada;
- as Edge Functions da P7.5 continuam pendentes de republicação live;
- Security Advisors live NÃO foram executados nesta rodada.

## Ordem para ativar em produção
1. Conferir schema/policies/grants live.
2. Aplicar/validar a migration 030.
3. Publicar `admin-auth-sessions` com `verify_jwt=true`.
4. Republicar as funções P7.5 pendentes.
5. Rodar Security Advisors e Performance Advisors.
6. Testar revogação com usuário de teste em dois dispositivos.
7. Somente então habilitar `authSessionRevocationReady` no Admin.

## Limite técnico
Remover uma linha de `auth.sessions` invalida a sessão/refresh token; JWT de acesso já emitido pode permanecer válido até `exp`. Para ações de risco máximo, a fase seguinte deve validar o claim `session_id` contra `auth.sessions` no servidor.
