# P7.8 — Ativação Controlada da Revogação Auth — v14.7

Data: 15/08/2026

## Objetivo
Eliminar a flag manual de ativação e impedir que o Admin exponha o botão de revogação antes de o backend P7.6/P7.7 estar realmente operacional.

## Implementado
- `authSessionRevocationReady` passa para modo `auto`.
- Admin executa `admin-auth-sessions {action: status}` após autenticação.
- O botão **Revogar login em todos os dispositivos** só é habilitado quando o backend confirma `ready`, `live_session_guard` e `revocation_rpc`.
- Falha de função, migration ausente ou guard indisponível mantém a ação desabilitada e explica o motivo.
- Após erro durante revogação, o Admin refaz o probe e pode desabilitar o botão novamente.
- `admin-auth-sessions/status` aceita o próprio administrador como alvo de diagnóstico quando `user_id` não é informado.

## Estado live
O conector Supabase caiu durante a primeira chamada desta fase. Migration/deploy/advisors/teste em dois dispositivos NÃO foram executados nesta sessão.

## Ordem de ativação live
1. Aplicar 030 (se pendente).
2. Aplicar 031.
3. Republicar as Edge Functions P7.7 com `verify_jwt=true`.
4. Publicar `admin-auth-sessions` desta P7.8.
5. Abrir Admin: o probe deve habilitar o botão automaticamente.
6. Testar com conta de teste em dois dispositivos.
7. Revogar e confirmar `session_revoked` no dispositivo revogado antes do `exp`.
8. Rodar Security/Performance Advisors.
